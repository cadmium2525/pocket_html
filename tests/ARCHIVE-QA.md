# ZIPファイルの取り出し確認

```sh
node scripts/make-archive-fixture.mjs
npm run dev
```

`http://localhost:43186` の **ZIPを選んで展開** を使います。

1. `tests/artifacts/archive-files.ZIP` を開く。HTMLなしでも5件が表示され、日本語名、空ファイル、別フォルダーの同名ファイルを確認する。
2. `資料/説明.txt` の **保存** から `説明.txt` をダウンロードする。UTF-8の原文68バイトと一致することを確認する。
3. `data/sample.bin` と `資料/説明.txt` だけを選び、**選択分をZIPにする → ZIPを保存**。生成ZIPは選択した2件だけで、パスと全バイトが原文と一致する。
4. `same.txt` で絞り込むと2件になり、**選択を解除 → 表示中を選択** で2件25バイトを選べる。検索で隠れた選択も件数に含む。選択を変えると以前の保存用ZIPは無効になり、再作成できる。
5. 一致しない検索語、空ZIP、壊れたZIPで、それぞれ空表示または読み取りエラーを確認する。閉じて別のZIPを開ける。
6. 任意のHTML入りZIPを取り出し用に開き、HTMLの実行画面に移動しないことを確認する。`dist/` で絞り込み・選択・保存する操作を確認する。
7. 320×568、390×640と高さの短い画面で、一覧と保存ボタンにスクロールで辿り着けること、横にはみ出さないことを確認する。
8. 大容量モードで33MiB素材のZIPを一覧表示し、閉じる・再選択を行えることを確認する。通常のViewerのZIP読み込みも確認する。

2026-10-20、WindowsのChromiumで、上記の一覧表示・個別ダウンロード・選択ZIPの全バイト比較・フォルダー絞り込み・空／破損ZIP・33MiB素材の展開を確認しました。320×568、390×640、390×420で横にはみ出さず、内容をスクロールして操作できることも確認しました。既存ViewerのZIP統合確認9項目（モジュール・JSON・画像・WebGLなど）も通過しています。

Web Shareは実際の選択データを `navigator.canShare` に渡して判定し、対応しない選択は無効化します。iPhone実機の共有シートと「ファイルに保存」の完了確認は未実施です。

自動テストはZIPのパス、データ、上限、CRC、名前の扱い、選択内容、読み込み中止を確認します。

## ファイル名だけが表示される問題への修正

2026-10-20、iPhoneのスクリーンショットで見つかった空表示に対し、ダイアログと内容を通常のブロック配置に変更しました。高さが未確定のflexダイアログ内で一覧部分を縮める配置を避け、画面の高さを超える場合はダイアログ全体をスクロールします。Safari固有の再現は未確認です。

また、端末のファイル提供元から届く `AbortError` をユーザーによるキャンセルと混同して無視していた処理を修正しました。自分のAbortControllerが中止された場合だけ表示を抑え、それ以外の読み込み中断は再選択の案内を表示します。`AbortError`、`NotReadableError`、`NotFoundError` と明示的な中止を区別する回帰テストを追加し、30件の自動テスト、構文チェック、公開用ビルドが通過しました。

この修正後は操作用ブラウザーが接続されておらず、画面やダウンロードの再確認はできていません。上記のChromium確認は修正前の機能確認です。iPhone実機では、小さいZIPの一覧・個別保存、不正ZIPのエラー、閉じて再選択、短い画面で下部の保存操作に辿り着けることを確認してください。
